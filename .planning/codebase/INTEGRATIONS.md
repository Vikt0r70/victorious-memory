# External Integrations

**Analysis Date:** 2026-05-25

## APIs & External Services

**LLM Providers:**
- OpenAI-compatible API - Used for memory extraction (LLM-powered analysis of conversations)
  - SDK/Client: `httpx` (async HTTP client) — `apps/api/app/domains/providers/gateway.py`
  - Auth: `LLM_API_KEY` env var, or per-provider `api_key` in DB (`provider_configs` table)
  - Format: `POST {base_url}/chat/completions` with `Authorization: Bearer {api_key}`
  - Configurable per role (`extraction`, `edge_detection`, `consolidation`) via UI at `/api/providers`
- Anthropic API - Alternative LLM backend
  - SDK/Client: `httpx` — `apps/api/app/domains/providers/gateway.py:_anthropic_complete`
  - Auth: `x-api-key` header + `anthropic-version: 2023-06-01`
  - Format: `POST {base_url}/v1/messages` with separate `system` field
  - Fallback hierarchy: DB provider config → env var defaults

**Embeddings:**
- sentence-transformers (BAAI/bge-small-en-v1.5) - 384-dim embedding model
  - Runs IN-PROCESS (not an external service) — `apps/api/app/domains/search/embeddings.py`
  - Lazy-loaded on first call, persisted in Docker volume (`hf_cache`)
  - Model downloaded from HuggingFace Hub on first run
  - Note: The `.env.example` references `EMBEDDING_URL` (for HuggingFace TEI), but the actual implementation uses `sentence-transformers` in-process — no external embedding service required

**Plugin Framework:**
- @opencode-ai/plugin 1.15.10 - OpenCode plugin API
  - Used by: `apps/plugin/victorious.js`
  - Hooks registered:
    - `experimental.chat.system.transform` → inject memory context into system prompt
    - `chat.message` → track user messages, trigger ingest on threshold
    - `tool.execute.after` → capture tool call outputs
    - `session.created` → detect workspace project
    - `session.idle` → flush pending exchange

**MCP Protocol:**
- MCP (Model Context Protocol) - Exposes 5 tools for agent memory interaction
  - Server: `apps/mcp/server.py` (Python, stdlib-only, stdio transport)
  - Protocol version: `2024-11-05`
  - Tools exposed: `search_memories`, `get_context`, `save_memory`, `list_memories`, `get_activity`
  - Connects to Victorious Memory API via `VICTORIOUS_API_URL` env var (default `http://localhost:8080`)

## Data Storage

**Databases:**
- PostgreSQL 16 with pgvector extension
  - Image: `pgvector/pgvector:pg16` — `docker-compose.yml`
  - Connection: `DATABASE_URL` env var (format: `postgresql+asyncpg://victorious:{password}@db:5432/victorious`)
  - Client: SQLAlchemy 2.0+ with asyncio + asyncpg driver — `apps/api/app/database.py`
  - Creates `vector` extension on startup via `CREATE EXTENSION IF NOT EXISTS vector`
  - 9 tables: `projects`, `memories`, `memory_edges`, `exchanges`, `extraction_jobs`, `timeline_entries`, `provider_configs`, `activity_log`, `app_settings` — `apps/api/app/models.py`
  - Vector column: `memories.embedding` → `Vector(384)` column with IVFFlat index for cosine similarity
  - Raw SQL for job claiming uses `FOR UPDATE SKIP LOCKED` — `apps/api/app/worker.py:_claim_next_job`

**File Storage:**
- Local filesystem only (no cloud storage)
  - Docker volumes for persistence: `pgdata` (PostgreSQL data), `hf_cache` (HuggingFace model cache) — `docker-compose.yml`

**Caching:**
- In-memory only — `@lru_cache` on embedding model load — `apps/api/app/domains/search/embeddings.py`
- HuggingFace model cached on disk via Docker volume (`hf_cache`)

## Authentication & Identity

**Auth Provider:**
- None currently — API is open (CORS allows all origins: `allow_origins=["*"]`) — `apps/api/app/main.py`
- API keys for LLM providers stored in `provider_configs` table (`api_key` column) — not returned in API responses (security)

**Session Tracking:**
- Session IDs generated by plugin (`opencode-{timestamp}`) — `apps/plugin/victorious.js`
- Exchanges tracked per session in `exchanges` table — `apps/api/app/models.py`

## Monitoring & Observability

**Error Tracking:**
- None external — Python `logging` module with structured format: `%(asctime)s | %(levelname)-8s | %(name)s | %(message)s` — `apps/api/app/main.py`
- Activity log stored in `activity_log` table — queryable via `/api/activity` endpoint and MCP `get_activity` tool

**Logs:**
- Console (stdout) for API — structured logging via `logging.basicConfig`
- Plugin: Optional file logging via `VICTORIOUS_LOG_FILE` env var + `VICTORIOUS_DEBUG` toggle — `apps/plugin/victorious.js`

**Health Check:**
- `GET /health` — returns `{"status": "ok", "version": "0.1.0"}` — `apps/api/app/main.py`
- Database health check via `pg_isready` in Docker Compose — `docker-compose.yml`

## Environment Configuration

**Required env vars:**
- `DATABASE_URL` — PostgreSQL connection string (default: `postgresql+asyncpg://victorious:victorious@localhost:5432/victorious`)
- `LLM_BASE_URL` — LLM provider endpoint (default: `http://localhost:7777/v1`)
- `LLM_MODEL` — Model name (default: `gpt-5-mini`)
- `DB_PASSWORD` — PostgreSQL password for Docker Compose
- `NEXT_PUBLIC_API_URL` (frontend) — API base URL (default: `http://localhost:8080/api`)
- `VICTORIOUS_API_URL` (plugin/MCP) — API base URL (default: `http://localhost:8080`)

**Secrets location:**
- `.env` file (gitignored) at project root — loaded by Pydantic Settings and Docker Compose
- Provider API keys stored in `provider_configs` database table
- Frontend env: `apps/web/.env.local`

## Webhooks & Callbacks

**Incoming:**
- None — the API is a standard REST service, no external webhook endpoints

**Outgoing:**
- LLM API calls to user-configured provider endpoints — `apps/api/app/domains/providers/gateway.py`
- HuggingFace Hub (model download on first run) — via `sentence-transformers` library
