## Task 3: Add Model Dropdown with API-Driven Discovery

**Goal:** Replace the plain text model `<input>` with a dropdown that fetches available models from the backend's `/providers/{id}/models` endpoint.

<read_first>
- apps/web/components/modals/ProviderConfigModal.tsx (current model input field)
- apps/web/lib/api.ts (providersApi.listModels method)
- apps/api/app/domains/providers/router.py (GET /providers/{id}/models endpoint)
</read_first>

<action>
1. In `ProviderConfigModal.tsx`:
   - Add state: `const [availableModels, setAvailableModels] = useState<string[]>([]);`
   - Add state: `const [loadingModels, setLoadingModels] = useState(false);`
   - Add effect: when `providerType` changes (and we're editing an existing provider), call `providersApi.listModels(provider.id)` to populate dropdown:
     ```typescript
     useEffect(() => {
       if (provider?.id) {
         setLoadingModels(true);
         providersApi.listModels(provider.id)
           .then((res) => {
             const models = res.models?.map((m: any) => m.id || m.name) || [];
             setAvailableModels(models);
           })
           .catch(() => setAvailableModels([]))
           .finally(() => setLoadingModels(false));
       }
     }, [providerType, provider?.id]);
     ```
   - Replace the plain `<input>` for model with a `<select>` dropdown when `availableModels.length > 0`, otherwise keep `<input>` as fallback:
     ```tsx
     {availableModels.length > 0 ? (
       <select ...>
         <option value="">Select a model...</option>
         {availableModels.map((m) => (
           <option key={m} value={m}>{m}</option>
         ))}
       </select>
     ) : (
       <input ... placeholder="e.g. gpt-4o" ... />
     )}
     ```
2. For new providers (not yet saved), keep the text input since there's no provider ID to query models with.
3. When a template is selected, auto-fill the model from the template (already works, keep this behavior).
</action>

<acceptance_criteria>
- Editing an existing provider shows a model dropdown populated from API
- The `providersApi.listModels(id)` method is called at least once when editing a provider
- New provider creation still uses text input for model
- Template selection still auto-fills model field
- `npx tsc --noEmit` passes
</acceptance_criteria>
