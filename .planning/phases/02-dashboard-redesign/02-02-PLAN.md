<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API response → page state | Untrusted backend data crosses into React state |
| User input → graph rendering | Search/filter strings pass into force-graph props |
| Memory content → DOM | Extracted memory text rendered in tables/cards |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Cross-Site Scripting | Dashboard, Review, Memory, Graph pages | mitigate | React's default escaping prevents XSS. All memory content is passed as React children (text nodes). No `dangerouslySetInnerHTML` is used in any page. |
| T-02-02-02 | Information Disclosure | ErrorBanner on all pages | mitigate | ErrorBanner displays only `err.message`. All `console.error` calls are removed. Implementors must ensure no stack traces or internal paths leak into `err.message`. |
| T-02-02-03 | Denial of Service | Graph Explorer Canvas | accept | Desktop-only target. Existing API limits nodes to 120. react-force-graph-2d handles Canvas optimization. No infinite loops in physics simulation. |
| T-02-02-04 | Information Disclosure | Jobs page error handling | mitigate | Same as T-02-02-02. ErrorBanner never displays raw job payloads or internal server paths. |
| T-02-02-05 | Spoofing | Review Queue button actions | mitigate | All approve/reject API calls use the existing authenticated `memoriesApi` client. Loading states prevent double-submission. |
</threat_model>
