    4. **Add `validate_config()` method** (NEW — per D-01, D-02, D-03):
       Add this method AFTER `_resolve_config()` and BEFORE `complete()`:
       ```python
       async def validate_config(self, model_role: str) -> tuple[str, str, str, str, int]:
           """Resolve and validate provider configuration for a role.

           Raises ProviderNotConfiguredError if no config exists or API key is empty.
           Returns the validated (provider_type, base_url, model, api_key, max_tokens).
           """
           config = await self._resolve_config(model_role)
           provider_type, base_url, model, api_key, max_tokens = config

           if not api_key or not api_key.strip():
               raise ProviderNotConfiguredError(
                   f"Provider for role '{model_role}' has no API key configured"
               )

           return config
       ```
       **Design rationale:** `validate_config()` is a separate method (not inline in `complete()`) because:
       - The test endpoint calls `validate_config()` first, then `complete()` — giving a clean 400 before attempting an HTTP call.
       - The extraction worker calls `complete()` directly — it benefits from `_resolve_config()` but doesn't need the pre-validation gate (it handles errors via retry).
       - The `complete()` method itself does NOT call `validate_config()` — this keeps backward compatibility. The worker already has retry logic for provider errors.

    5. **Rewrite `complete()` method:**

       - Calls `_resolve_config()` (NOT `validate_config()` — callers opt-in to validation)
       - Builds `litellm_model = f"{provider_type}/{model}"`
       - Constructs kwargs dict with `model`, `messages`, `api_key`, `api_base`, `max_tokens`, `timeout=30.0`
       - If `response_format == "json"`: adds `response_format={"type": "json_object"}`
       - Calls `await litellm.acompletion(**kwargs)`
       - Returns `response.choices[0].message.content or ""`
       - Catches LiteLLM exceptions and maps them:
         - `litellm.Timeout` → `ProviderTimeoutError`
         - `litellm.AuthenticationError` → `ProviderError` (with "Authentication failed" message)
         - `litellm.RateLimitError` → `ProviderError` (with "Rate limited" message)
         - `litellm.BadRequestError` → `ProviderError` (with "Bad request" message)
         - `litellm.APIError` → `ProviderError` (generic "API error" message)
         - `Exception` → `ProviderError` (catch-all with "Unexpected error" message)

    6. **Remove `_openai_complete()` and `_anthropic_complete()` methods entirely.** LiteLLM handles all provider-specific schema translation internally.

    7. **Simplify `close()` method:**

           """LiteLLM manages its own HTTP client lifecycle."""
           pass
       ```

        url = f"{API}{path}"

    #!/usr/bin/env python3
    """Victorious Memory — Pipeline verification script.

    Quick manual check that the ingestion pipeline works.
    Usage: python scripts/verify_pipeline.py [--wait-worker]
    """

    from __future__ import annotations

    import json
    import sys
    import time
    import urllib.request
    import urllib.error

    API = "http://localhost:8080/api"
    WAIT_WORKER = "--wait-worker" in sys.argv


    def req(method: str, path: str, body: dict | None = None) -> tuple[int, dict]:
        url = f"{API}{path}"
        data = json.dumps(body).encode() if body else None
        headers = {"Content-Type": "application/json"} if body else {}
        request = urllib.request.Request(url, data=data, headers=headers, method=method)
        try:
            with urllib.request.urlopen(request) as resp:
                return resp.status, json.loads(resp.read())
        except urllib.error.HTTPError as exc:
            return exc.code, json.loads(exc.read())


    def main() -> None:
        print("Pipeline Verification")
        print("-" * 40)

        # 1. Ingest
        print("1. Ingesting synthetic exchange...")
        status, body = req("POST", "/ingest", {
            "session_id": f"verify-{int(time.time())}",
            "exchange": {
                "user": "What is the best way to handle database migrations?",
                "agent_parts": [{"type": "text", "content": "Use Alembic for database migrations with SQLAlchemy."}],
                "file_paths": [],
                "timestamp": "2026-05-25T12:00:00Z",
            },
        })
        assert status == 200, f"Ingest failed: {status} {body}"
        print(f"   ✅ exchange_id={body['exchange_id']} job_id={body['job_id']}")

        # 2. Verify exchange
        print("2. Checking exchange row...")
        status, body2 = req("GET", f"/exchanges/{body['exchange_id']}")
        assert status == 200, f"Exchange not found: {status}"
        print(f"   ✅ Exchange exists")

        # 3. Verify job
        print("3. Checking extraction job...")
        status, body3 = req("GET", f"/jobs/{body['job_id']}")
        assert status == 200, f"Job not found: {status}"
        print(f"   ✅ Job status: {body3['status']}")

        # 4. Activity log
        print("4. Checking activity log...")
        status, body4 = req("GET", "/activity?per_page=5")
        assert status == 200, f"Activity failed: {status}"
        items = body4 if isinstance(body4, list) else body4.get("items", [])
        recent = [a for a in items if a.get("event_type") == "extraction_started"]
        print(f"   ✅ Found {len(recent)} recent extraction_started events")

        # 5. Optional: wait for worker
        if WAIT_WORKER:
            print("5. Waiting for worker to claim job (max 30s)...")
            job_id = body["job_id"]
            for i in range(15):
                status, j = req("GET", f"/jobs/{job_id}")
                if j.get("status") in ("processing", "done", "failed"):
                    print(f"   ✅ Worker claimed job: {j['status']} (after {(i+1)*2}s)")
                    break
                time.sleep(2)
            else:
                print("   ❌ Worker did not claim job within 30s")
                sys.exit(1)

        print("\n✅ Pipeline verification passed!")


    if __name__ == "__main__":
        main()
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| VM2 API → LiteLLM library | In-process library call; LiteLLM makes outbound HTTPS to LLM providers |
| LiteLLM → External LLM APIs | Outbound HTTPS with API keys in headers (Authorization, x-api-key) |
| VM2 API → PostgreSQL | Provider configs (including API keys) stored in `provider_configs` table |
| Client → VM2 API | No auth — provider test endpoint accessible to anyone on network |
| Plugin → VM2 API | Plugin sends conversation data to /api/ingest without authentication |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | API keys in LiteLLM logs | mitigate | LiteLLM redacts API keys by default. Set `litellm.set_verbose = False` in gateway __init__. Verify no keys appear in docker logs. |
| T-02-02 | Information Disclosure | API keys in DB (plaintext) | accept | Provider configs store `api_key` as plaintext TEXT column. Accepted for localhost deployment (same as Phase 1 T-01-01 decision). |
| T-02-03 | Spoofing | SSRF via `api_base` parameter | accept | `base_url` in provider config could point to internal services. Accepted — no auth, localhost only, admin-controlled configs. |
| T-02-04 | Tampering | LiteLLM dependency supply chain | mitigate | Pin to `litellm>=1.86.0`. LiteLLM is a well-established YC-backed project (BerriAI). Transitive deps include `openai` (official) and `tiktoken` (official). |
| T-02-05 | Denial of Service | LiteLLM default 600s timeout | mitigate | Pass `timeout=30.0` per-request in `complete()`. Prevents hung requests from blocking the API. |
| T-02-06 | Information Disclosure | Conversation data in /api/ingest | accept | Ingested exchanges contain user conversation content. No auth on endpoint. Accepted — localhost deployment, same trust boundary as existing system. |
| T-02-07 | Elevation of Privilege | Synthetic test data in DB | accept | Verification scripts create test exchanges in production DB. Acceptable for development — no separate test DB. Clean up manually if needed. |
| T-02-SC | Tampering | pip install litellm (Dockerfile) | mitigate | slopcheck protocol: if slopcheck tooling is configured, scan. Otherwise accept — litellm is a verified, widely-used package. |
